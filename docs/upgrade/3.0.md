# Upgrading to 3.0

Extraction now returns an `ExtractionResult` instead of the bare schema, so the
schema can travel together with metadata about how it was built.

Two audiences are affected:

- **everyone calling `SchemaExtractor::extract()`**: one-line change;
- **custom `JsonSchemaMapperInterface` implementations**: return type change.

Standard usage through the built-in components is otherwise unchanged.

## `SchemaExtractor::extract()` returns an `ExtractionResult`

Read the schema from the `schema` property.

Before:

```php
$schema = $extractor->extract(Order::class);

echo json_encode($schema);
```

After:

```php
$result = $extractor->extract(Order::class);

echo json_encode($result->schema);
```

The value of `->schema` is exactly what `extract()` returned in 2.x
(`array<string, mixed>|object`), so anything downstream of it keeps working.

## Custom mappers return a `MappingResult`

`JsonSchemaMapperInterface::map()` now returns a `MappingResult`: the schema plus
the reference pointers emitted while building it. Reference pointers can only be
derived inside the mapper, because their shape depends on the mapper's own naming
and on the configured dialect.

Before:

```php
public function map(SerializedProjection $projection): JsonSchemaInterface
{
    return $this->buildSchema($projection);
}
```

After:

```php
public function map(SerializedProjection $projection): MappingResult
{
    return new MappingResult($this->buildSchema($projection), $this->refs);
}
```

## What you get in return: the `$ref` map

`ExtractionResult::$refs` maps every reference pointer the mapper emitted to the
class it denotes:

```php
$result = $extractor->extract(Order::class);

// $result->refs === [
//     '#/definitions/Customer'   => 'App\Model\Customer',
//     '#/definitions/StatusEnum' => 'App\Model\StatusEnum',
// ]
```

Pointers are keyed exactly as they appear in the document (`#/definitions/...` on
Draft-7, `#/$defs/...` on 2020-12), so they can be matched and rewritten directly
against the emitted schema. This is what makes it possible to relocate referenced
schemas, for instance hoisting them into an AsyncAPI `components/schemas` block and
rewriting every pointer to match.

Two things to keep in mind:

- **Inlined shapes carry no pointer**, so they are absent from the map. Only
  schemas the mapper actually referenced appear. With
  `ClassReferenceStrategy::Inline` the map is empty.
- **The root document is not listed.** Callers already know the class they asked
  to extract, and `#` is only ever emitted for that class.
